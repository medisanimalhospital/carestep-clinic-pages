# CARESTEP Clinic v7.3 · Guardian Response, Recovery Survey & Satisfaction

v7.3은 v7.2 질환별 Patient Journey Builder 위에 **보호자 반응·회복상태 설문·만족도·확인 필요 신호·Journey 결과 측정**을 추가합니다.

## 핵심 변경

### 1. Journey 단계별 보호자 설문
- 병원 Journey 편집기에서 각 D+ 단계별 `회복상태·만족도 설문` ON/OFF
- 설문은 **보호자 자동발송이 켜진 단계에서만** 함께 사용
- CARESTEP 기본 Journey 9종의 주요 단계에 설문 기본값 제공
- 자동발송 예약 시 1회용 설문 링크 생성
- SMS/LMS: 메시지 끝에 설문 링크 자동 추가
- 알림톡: 기존 권장 변수 `#{안내}`에 설문 링크를 함께 전달

### 2. 보호자 공개 설문 페이지
Worker가 `/survey/<one-time-token>` 페이지를 직접 제공합니다. 별도 웹서버나 새 도메인이 필요하지 않습니다.

설문 항목:
- 현재 상태: 호전 / 비슷 / 악화
- 식욕·섭취 상태 1~5
- 처방약·가정관리 시행 여부
- 걱정 증상 여부
- 후속관리 만족도 1~5
- 추천 의향 0~10
- 병원 연락 요청 여부
- 선택 자유메모

설문 링크는 강한 무작위 토큰을 사용하고 **D1에는 원문 토큰이 아니라 SHA-256 hash만 저장**합니다. 기본 유효기간은 발송 예정시각부터 14일입니다.

### 3. 확인 필요 자동 분류
**빠른 확인(urgent)**
- 상태 악화
- 걱정 증상 있음
- 병원 연락 요청

**주의 확인(watch)**
- 식욕 1~2점
- 가정관리 시행 어려움
- 만족도 1~2점

병원 후속관리 업무보드의 `💬 설문 확인` 탭과 전체 `🚨 확인 필요` KPI에 자동 반영됩니다. 확인 후 `확인 처리`할 수 있습니다.

### 4. 병원 설문 대시보드
후속관리 화면에서 최근 90일 기준:
- 설문 초대 수
- 응답률
- 평균 만족도
- 미확인 주의/긴급 응답
- 최근 응답의 회복 추세·식욕·관리 시행·만족도·추천의향

을 확인합니다.

### 5. HQ 설문 성과
HQ에 `보호자 설문` 메뉴를 추가합니다.
- 전체 설문 초대 / 응답률
- 평균 만족도
- 확인 필요 / 미확인 건수
- 병원별 설문 성과
- Patient Journey별 응답률·만족도·호전 응답 비율

HQ에는 자유메모 같은 개별 응답 내용을 표시하지 않고 집계값만 제공합니다.

## 개인정보 최소화
`guardian_surveys`에는 다음을 저장하지 않습니다.
- 보호자 이름
- 보호자 전화번호
- 환자명
- 주소 / 이메일

저장되는 것은 비식별 case key, Journey ID, D+ 단계, 응답 값, 설문 자유메모, 만족도, 확인 상태 등입니다. 자유메모 입력란에서도 개인정보를 적지 않도록 안내합니다.

## 자동발송과 설문의 관계
설문은 새로운 문자 1건을 추가 발송하는 방식이 아닙니다. **기존 D+ 자동발송 메시지 안에 설문 링크를 포함**합니다. 따라서 설문 링크 자체 때문에 메시지 건수가 +1 되지는 않습니다. 다만 SMS 글자수 증가로 SOLAPI에서 LMS로 분류될 수 있으므로 실제 과금 단가는 v7.0 `사용량 · 정산`에서 확인하세요.

실패 메시지를 재발송할 때 기존 메시지에 설문이 연결되어 있었다면 새 1회용 설문 링크를 다시 발급하고 이전 미응답 링크는 취소합니다.

### 알림톡 사용 시 주의
알림톡은 승인된 SOLAPI 템플릿 본문에 **`#{안내}` 변수가 실제로 포함되어 있어야** 설문 URL이 보호자에게 표시됩니다. 기존 승인 템플릿에 `#{안내}`가 없다면 설문 단계는 우선 SMS/LMS로 테스트하거나, 설문 링크를 포함할 수 있도록 알림톡 템플릿을 수정·재승인한 뒤 사용하세요.

### 확인 필요 신호의 성격
`urgent / watch` 분류는 **병원 업무보드에서 우선순위를 높이는 운영 신호**입니다. 응급환자 실시간 감시장치나 24시간 호출 시스템은 아닙니다. 후속관리 화면이 열려 있으면 약 2분 주기로 설문 현황을 갱신하고, 그렇지 않을 때는 다음 접속/새로고침 시 반영됩니다. 공개 설문에도 응급 변화가 있으면 설문 제출을 기다리지 말고 병원 또는 응급진료기관에 직접 연락하도록 안내합니다.

## 신규 D1 테이블
- `guardian_surveys`

Worker가 `CREATE TABLE IF NOT EXISTS`로 자동 생성합니다. **D1 Console에서 SQL을 직접 실행할 필요가 없습니다.**

## 요금제 권한
신규 feature: `guardianSurvey`
- PILOT: ON
- BASIC: OFF
- PRO: ON
- ENTERPRISE: ON

기존 `plan_catalog.features_json`은 최초 v7.3 요청에서 자동 보완됩니다.

## 추가 Worker Secret
**없습니다.**

기존 Secret과 D1 binding을 그대로 사용합니다.

## 배포 순서
1. Cloudflare Worker → `worker-paste-ready.txt` 전체 교체 → Deploy
2. 병원용 `index.html` 교체
3. HQ용 `hq.html` 교체
4. 브라우저 `Ctrl + Shift + R`
5. 병원 로그인 → 후속관리 → Patient Journey에서 설문 표시 확인
6. 테스트 케이스에서 설문 ON 단계 1건을 가까운 미래 시각으로 예약
7. 실제 문자 링크 열기 → 설문 응답
8. 병원 화면 `보호자 반응 · 설문 · 만족도`와 업무보드 `💬 설문 확인` 확인
9. HQ → `보호자 설문` 집계 확인

## 권장 첫 테스트
`고양이 요도폐색·FLUTD Journey`의 D+1 또는 `슬개골 수술 회복 Journey`의 D+3처럼 설문 기본값이 ON인 단계를 테스트합니다.

악화 / 걱정 증상 있음 / 연락 요청 중 하나를 선택해 제출하면 병원 화면의 `확인 필요`에 표시되어야 합니다.
